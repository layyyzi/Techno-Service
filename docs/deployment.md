# Хмарне розгортання ТехноСервіс

Це підготовлена конфігурація для одного Linux-сервера з Docker Compose та публічним DNS-іменем. Вона не означає, що хмарний стенд уже розгорнуто.

## Архітектура

Браузер → HTTPS (Caddy) → Python REST API (внутрішня мережа Docker) → SQLite (іменований том knowledge_data).
Caddy отримує і поновлює TLS-сертифікат. Порт Python не публікується назовні; лише порти 80 і 443 проксі.

## Запуск

1. Підготуй Linux VPS з Docker Engine та Compose v2. Налаштуй DNS A/AAAA для реального домену, відкрий TCP 80 і 443. Не відкривай порт 8000.
2. Клонуй репозиторій. Поки зміни проходять перевірку, використовуй гілку feature/cloud-security.
3. Скопіюй `.env.example` у `.env`, обмеж доступ до файлу (chmod 600 .env). Укажи реальне DNS-ім’я, пошту адміністратора та унікальний випадковий пароль завдовжки 16–128 символів. Не публікуй ці дані.
4. Виконай `docker compose up -d --build`. Перевір `docker compose ps` і `docker compose logs --tail=100 app proxy`.
5. Відкрий https://<твій-домен>. Увійди під створеним адміністратором, створи інструкцію, перевір її з іншого браузера. Перезапусти контейнер командою `docker compose restart app` і перевір, що інструкція збережена.

## Дані та обмеження

- Хмарний режим створює лише адміністратора та порожню БД. Демоакаунти та навчальні записи не створюються. Зміна змінної пароля не змінює пароль існуючого адміністратора.
- Не перенось локальну демонстраційну БД у production. Створення інших облікових записів через UI ще потребує реалізації.
- Іменований том зберігає дані при перезапуску та перебудові контейнера. Команда `docker compose down -v` видаляє томи: не використовуй її з потрібними даними.
- Для резервного копіювання зупини застосунок і скопіюй вміст тому або використовуй SQLite Backup API. Том не замінює резервну копію.
- Поточний HTTP-сервер на стандартній бібліотеці та обмежувач входу в пам’яті призначені для однопроцесного навчального пілота, не для високонавантаженого production. За проксі усі клієнти мають спільний ліміт за IP; перед корпоративним використанням потрібне окреме обмеження на проксі або налаштування довірених проксі.
- HTTPS завершується на Caddy. Не запускай app із відкритим зовнішнім портом.
- Хмарне розгортання та відновлення резервної копії потрібно підтвердити фактичними перевірками.

## Локальний режим

Без змінних TECHNO_PUBLIC_URL і TECHNO_BIND: `python server.py --open`. Демонстраційні ролі залишаються доступними. GitHub Pages працює окремо з браузерним сховищем.
