# ТехноСервіс

Корпоративна база знань для IT-підтримки та обслуговування обладнання.

**[Відкрити публічну демоверсію](https://layyyzi.github.io/Techno-Service/)** · [Поточна розробка](https://github.com/layyyzi/Techno-Service/tree/feature/cloud-security) · [Лабораторні роботи](https://github.com/layyyzi/laba-1-upr-IT)

Проєкт кваліфікаційної роботи «Розробка та впровадження хмарного прикладного сервісу управління корпоративними знаннями та технічною документацією».

## Ідея та можливості

Мета — централізувати технічну документацію та скоротити час пошуку рішень типових несправностей.

- Вхід і три ролі: читач, редактор, адміністратор.
- Пошук, категорії, створення, редагування, архівування та історія версій інструкцій.
- Підбір до п’яти інструкцій за типом обладнання, моделлю та симптомами з поясненням збігів.
- Підготовка тексту звернення до підтримки та повідомлення про неточності.
- Перегляд користувачів і зміна ролей адміністратором.

## Архітектура

Поточна серверна версія: браузер → Python REST API → SQLite.

Запланований хмарний стенд: браузер → HTTPS / Caddy → Python API у Docker → SQLite на постійному томі. Публічна демоверсія GitHub Pages не підключена до серверної бази даних.

## Запуск локально

Потрібен Python 3.11 або новіший. Додаткові Python-пакети не потрібні.

```powershell
git clone https://github.com/layyyzi/Techno-Service.git
cd Techno-Service
python server.py --open
```

Для перевірки поточної гілки розробки перед запуском виконай `git switch feature/cloud-security`. Якщо у Windows Python доступний через `py`, використовуй `py -3 server.py --open`. Якщо вже маєш локальний Python у .runtime, можна запустити `.\.runtime\python\python.exe server.py --open`. Також доступний start-demo.cmd.

Адреса: http://127.0.0.1:8000. Зупинка: Ctrl+C. Інший порт: `python server.py --port 8080 --open`.

| Роль | Пошта | Пароль |
|---|---|---|
| Читач | reader@demo.test | Demo2026! |
| Редактор | editor@demo.test | Demo2026! |
| Адміністратор | admin@demo.test | Demo2026! |

Ці дані призначені лише для навчального демо. У хмарному режимі гілки розробки створюється окремий адміністратор з паролем із конфігурації; демонстраційна БД не допускається.

## Перевірки

```sh
python -m unittest -v
python build_public_demo.py
node --test test_public_demo.mjs
```

На Windows з локальним Python заміни python на `.\.runtime\python\python.exe`. Публічне демо збирається в dist. [GitHub Actions](https://github.com/layyyzi/Techno-Service/actions).

## Структура коду

| Файл | Призначення |
|---|---|
| server.py | HTTP-сервер, API, сеанси й перевірка прав |
| database.py | SQLite, користувачі, документи, версії та журнал входу |
| diagnostics.py | Підбір рішень |
| public/ | HTML, CSS і JavaScript |
| build_public_demo.py | Збирання статичного демо |
| test_api.py / test_public_demo.mjs | Автоматичні перевірки |

Локальні зміни зберігаються в data/knowledge.sqlite3. Для перенесення зупини сервер і скопіюй папку data. Не публікуй реальні корпоративні дані, файли .env або БД у репозиторії.
